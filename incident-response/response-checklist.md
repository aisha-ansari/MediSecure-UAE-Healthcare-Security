# Security Incident Response Checklist

## Phase 1: Identification

- [ ] Record the alert and incident start time.
- [ ] Identify the affected account, identity, and resource.
- [ ] Validate the alert using available evidence.
- [ ] Assign an incident owner and preliminary severity.
- [ ] Preserve relevant logs and evidence.

## Phase 2: Investigation

- [ ] Review authentication and audit events.
- [ ] Identify suspicious or unauthorized activity.
- [ ] Establish the time period and potential scope.
- [ ] Determine what information may have been affected.
- [ ] Document evidence gaps and uncertainties.

## Phase 3: Containment

- [ ] Restrict confirmed unauthorized access.
- [ ] Revoke compromised credentials where appropriate.
- [ ] Correct unintended public exposure or excessive permissions.
- [ ] Preserve evidence before making changes where practical.
- [ ] Record containment actions.

## Phase 4: Eradication and Recovery

- [ ] Remove the identified cause of the incident.
- [ ] Apply approved corrective controls.
- [ ] Verify that access restrictions work as intended.
- [ ] Restore affected services or data if necessary.
- [ ] Confirm system integrity.

## Phase 5: Notification and Governance

- [ ] Escalate to appropriate security and privacy stakeholders.
- [ ] Obtain legal or compliance advice where required.
- [ ] Determine applicable notification obligations.
- [ ] Record management decisions and communications.

## Phase 6: Lessons Learned

- [ ] Document the incident timeline and findings.
- [ ] Assign remediation owners and deadlines.
- [ ] Identify improvements to monitoring and prevention.
- [ ] Review whether response procedures worked effectively.
- [ ] Schedule follow-up testing.

## Exercise Limitation

This checklist is intended for an educational tabletop exercise. Actual incident handling must follow the organization's approved procedures and applicable legal obligations.
